{% comment %} Sprint 7 (7.2.3 responsive audit): `relative` lives on this shared row wrapper, NOT on each individual `
` below, and both `
` share `name="dashboard-toolbar"`. Two reasons, found by re-deriving the CSS by hand (no Playwright in this environment): 1. Each panel below is `absolute right-0`. With `relative` on the *individual* `
` (the pre-existing Settings-only behavior), the containing block for that `right-0` is the trigger's own box -- correct when there is exactly one trigger flush against this row's right edge, but wrong now that Settings sits to the *left* of Palette: its panel would anchor to Settings' own right edge (well left of the row's actual right edge) and the full `calc(100vw-2rem)` panel would overflow off the left edge of the viewport at narrow widths. Hoisting `relative` to this wrapper makes both panels resolve `right-0` against the *row's* right edge instead, which -- at every breakpoint here (mobile: this wrapper stretches full width via the parent's default `align-items: stretch` under `flex-col`; `sm:` and up: `sm:justify-between` on the parent pushes this wrapper flush against the container's own right edge) -- coincides with the page content's right edge, matching the already-working single-dropdown case exactly, for both triggers. 2. Plain `
` elements never coordinate with each other, so without `name`, a user could open both Settings and Palette at once, stacking two cards on top of each other. Matching `name` values opt into the HTML living standard's native "exclusive accordion" behavior (opening one auto-closes the other) -- no JS, per NFR-01/§9.2's "no JS menu library" rule. Not confirmed in a real browser (see docs/ARCHITECTURE.md's Playwright gap); older browsers without support for `name` simply keep today's independent-open behavior, so this is a strict improvement with no regression path. {% endcomment %}
