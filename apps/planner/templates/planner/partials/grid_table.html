Sprint 7 (7.2.3 responsive audit) -- two fixes found by re-deriving the CSS by hand, no Playwright in this environment: 1. `table-fixed` + `w-full` inside this `overflow-x-auto` wrapper means the table is always sized to *exactly* the wrapper's width -- it can never overflow it, so the wrapper's horizontal scroll never actually triggers; instead, `table-fixed`'s equal-column-split behavior just squeezes all 7 day columns down to illegibly-thin widths on narrow viewports (NFR-04 wants "readable, scrollable," not "shrunk"). Added `min-w-[760px]` to the `` (below) as a floor -- the 64/80px time column (`w-16 sm:w-20`) plus 7 columns at roughly 100px each, a legible minimum for a block's label plus its hover-control icons -- so `overflow-x-auto` now has something to actually scroll below that width, while `w-full` still lets the table grow to fill wider viewports exactly as before. 2. A `` (below) can legitimately render with *zero* `
`s if all 7 of a row's cells are `'occupied'` by rowspans from blocks above (e.g. 7 same-time, multi-slot blocks, one per day) -- per the template contract above, an `'occupied'` cell renders nothing at all. Fixed by adding `h-12` directly to the time-label `` (below), which always renders regardless of how many (if any) day cells render in that same row -- a guaranteed floor, not a per-row `{% if %}` computed span (PRD R2).
